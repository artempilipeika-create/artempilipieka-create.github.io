# Клиентский альбом кухни · зафиксированный формат

Утверждено пользователем 27.10.2026: автоматический запуск кнопкой на сайте,
существующий MF_IMAGE_API_KEY. Основной инструмент продажи — визуализация кухни.

Формат `mf-kitchen-album-v1`: четыре страницы A4, альбомная ориентация,
светлый фон, тёмно-зелёные акценты, крупные изображения, русская типографика.
Сервер использует вложенные лицензированные шрифты DejaVu.

1. Обложка с главным видом кухни, именем проекта и брендом Martin Forest.
2. Второй точный ракурс из конструктора с явной подписью источника.
3. Реальные названия материалов корпуса, фасадов, цоколя и столешницы с образцами
   рядом с каждым названием. Образцы выбираются по сохранённым ID материалов из
   того же каталога, что и в конструкторе; поддерживаются пользовательские текстуры
   из архивов. Текстура, образец без текстуры, цвет без текстуры и отсутствие
   изображения имеют разные подписи. Для нескольких декоров показывается каждый.
   Отсутствующие значения требуют выбора; переполнение не скрывает материалы.
4. Комплект для самостоятельной сборки. Стоимость — после расчёта.
   Доставка отдельно; сборка и установка не включены. Комплектность и фурнитура
   подлежат согласованию. Техника и декор на визуализации не включаются автоматически.

Закупочные цены, маржа, внутренние идентификаторы и исходные файлы в альбом не входят.
Предварительные 590 BYN за отдельный ПН-600 не являются ценой всей кухни.
Технический PDF API сохранён для прежних интеграций; отдельного окна генерации
в конструкторе больше нет.

## Один фоторендер → готовый PDF · уточнение 28.10.2026

Пользователь показал два окна с разными рендерами и уточнил: один платный
фоторендер должен автоматически попадать в обсуждённый PDF. Старое окно
«Альбом для клиента» с отдельным запуском и загрузкой картинок удалено из UI.
Все кнопки альбома открывают один четырёхстраничный клиентский альбом.

«Альбом кухни» сохраняет проект, ищет уже оплаченный результат и сразу собирает
из него PDF. Если результата нет, пользователь один раз отмечает согласие и
нажимает «Создать фоторендер и PDF». Используется «Живой интерьер» с прежними
1536 × 1024, quality=high и n=1. Провайдер, промпт и настройки качества не менялись.
Второй вид — бесплатный кадр конструктора; образцы материалов — локальный каталог.

После ответа генератора то же исходное изображение автоматически передаётся
в клиентский PDF. Дополнительная загрузка файла и обязательная галочка проверки
не нужны. Остаются предпросмотр и кнопка «Скачать альбом · PDF». Проверить геометрию
и материалы перед отправкой клиенту рекомендуется текстом. Генеративная картинка
не меняет геометрию, данные БАЗИС или выбранные материалы проекта.

Ожидающий результат проверяется бесплатным GET; повторных платных POST нет.
Если сборка PDF не удалась, кнопка повторяет только сборку из сохранённого фото.
Повторная генерация для неизменённой кухни не предлагается. Ошибочный или
неопределённый оплаченный запуск блокирует новый запрос для той же кухни.

## Хранение и защита от повторной оплаты

Ключ остаётся на сервере. Квитанции и изображения хранятся в приватном каталоге
MF_PRIVATE_STORAGE_ROOT/kitchen-renders. Все маршруты проверяют владельца проекта.
Повторное открытие, другой браузер и увеличение номера сохранения используют
серверный индекс по содержимому кухни. Выбор шкафчика и режим редактора в ключ
не входят; размеры, материалы, техника, помещение и native source identity входят.

До обращения к провайдеру каталог индекса создаётся эксклюзивно. Даже два разных
request_id из двух вкладок не вызывают генератор дважды для одной кухни. При
прерывании индекс не удаляется: проверка не повторяет потенциально платный запрос.
Прежняя защита по request_id и старые квитанции сохраняются. Старые изображения
переиспользуются только при совпадении сохранённой версии либо точной подписи
исходного кадра; по одному project_id соответствие не предполагается.

Проверки используют заглушки провайдера. Платная генерация при разработке не нужна.
